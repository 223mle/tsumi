# unslop の検査で確かめること

unslop は、読み手が対象・範囲・動作を特定できる文章を書くためのスキルである。
`find-ambiguous.py` は、見直す候補の抽出を補助する。候補ゼロは文章の合格を意味しない。

## 文書を保存したら候補を確認する

スキルを置いたディレクトリから実行する。

```sh
python3 scripts/find-ambiguous.py README.md
```

出力には対象ファイル、行番号、候補語、元の行が含まれる。ファイルは変更しない。
読み込めないファイルがある場合は終了コード2で停止する。候補があっても正常終了する。

- 対象・範囲が不明な場合は、具体名、対応する場所、確認先を本文へ補う。
- 増える一覧は全件を書き写さず、例と管理元へのリンクを示す。
- 「文書 API の接続先」のように既に対象が分かる箇所は、候補に出ても機械的に消さない。
- コードブロック、コード識別子、リンクの宛先は文の書き換え対象から外す。

固定した語を探す検査なので、未知の抽象表現や意味の誤りは検出できない。
原文の条件を落としていないか、節が役割に合っているかは、本文と原文の照合で確認する。
回帰評価の条件と結果は [evals/prose](../evals/prose/README.md) に記録する。

## hook はスキルと文章評価を置き換えない

[yomiyasu の検査と hook](https://github.com/nanaism/yomiyasu/blob/main/README.md) を調査した。
参考にしたのは、表現の候補抽出を意味判断と分ける設計と、検査した本文と返す本文の一致を確かめる設計である。
今回の検出スクリプトは独自実装で、yomiyasu のコードは取り込んでいない。

yomiyasu の hook は登録済み原稿の検査記録を確認する補助であり、すべての文書執筆でスキルを
自動発動させるものではない。詳細は [hook の実装](https://github.com/nanaism/yomiyasu/blob/main/scripts/yomiyasu_hook.py)
と [利用手順](https://github.com/nanaism/yomiyasu/blob/main/docs/tools.md) にある。

unslop でも、スキルを読む入口と、保存後の検査漏れを検出する hook は別に扱う必要がある。
現時点では hook を追加・インストールしていない。文書執筆は unslop に振り分ける既存の
`tsumi-mode` の指示を維持する。自動発動の保証はなく、今回の評価も指定したスキルを読ませる条件である。

hook を追加する場合は、対象ファイル、入力と出力の記録、編集後の再検査、正常時に処理を妨げないことを
利用環境ごとに確かめる必要がある。スキルを読んだ記録や本文ハッシュがあっても、読みやすさの保証にはならない。
