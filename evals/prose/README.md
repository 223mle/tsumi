# clear-japaneseの清書評価

`requests.json`は実際の修正指摘を一般化した入力、`rubric.md`は出力の判定基準である。題材は架空で、元の会話の会社名や業務データは含まない。トリガー評価とは別に、生成された本文の品質を確認する。

## 再実行

1. 比較する二つの版から`skills/clear-japanese/`を、それぞれ中立な名前の一時フォルダへコピーする。コピーした全ファイルが比較対象と一致することを確認する。
2. 各版・各試行で新しいエージェントを使い、同じモデルと設定で3回実行する。各エージェントにはスキルと入力だけを渡し、採点基準や他の出力を見せない。
3. 下記の依頼を使う。各ケースの出力を別ファイルで保存し、スキルと参照資料を読んだ実行記録も残す。
4. 出力を匿名ラベルで混ぜ、原文と`rubric.md`を別の採点者へ渡す。モデルや版の対応は伏せる。`outputs.json`は対応表を含む実行記録なので、採点者にはそのまま渡さず、`label`・`case`・`text`だけを取り出したファイルを渡す。各必須条件の合否と出力中の根拠を記録する。
5. 主担当もすべての出力を読み、採点と照合する。旧版の失敗、新版の失敗、回帰、判定の不一致を分けて報告する。全体の文字数だけで合否を決めない。

依頼文は次を使い、`依頼.md`にはケースのIDと`prompt`だけを配置する。

> 日本語の清書をお願いします。{スキルのパス} を読み、その手順と必要な参照資料を使って、{依頼のパス} の各件を処理してください。出力は {保存先} にIDごとに .md ファイルとして保存してください。各ファイルは清書後の本文のみ。入力とスキルは変更せず、この2つ以外の文脈を調査する必要はありません。完了したら保存先のみ報告してください。

採点は意味と構成を扱うため、現時点では自動合否判定ではない。短い文書でも膨らませないケースと、長く重複した原文を整理するケースの両方を残す。重大な制約を削らないケースも同時に回す。
