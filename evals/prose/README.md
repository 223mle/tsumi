# unslopの清書・起草評価

`requests.json`は実際の修正指摘を一般化した入力、`rubric.md`は出力の判定基準である。題材は架空で、元の会話の会社名や業務データは含まない。トリガー評価とは別に、生成された本文の品質を確認する。採点は意味と構成を扱うため、自動合否判定ではない。

## ケースは6件までに絞る

ケースは、実際に失敗を捕まえられる核心的なものだけを残す。`scripts/check-skills`は、`requests.json`が6件を超えると落ちる。`requests.json`のケースと`rubric.md`のケース別条件が1対1で対応しない場合も落ちる。

- ケースを足すのは、実際の失敗を旧版で再現できたときだけにする。
- 6件を超える場合は、1件外してから足す。外す候補は、全件の評価で2回続けて旧版も新版も3/3だったケースである。候補がない場合は、捕まえる失敗がほかのケースと最も重なるものを外すか、足すのを見送る。
- 外したケースは`requests.json`と`rubric.md`から削除し、下の「外したケース」に記録する。原文はgitの履歴から戻せる。

## 1回の評価

作業の途中は、変更に関わるケースだけを新版で1回ずつ回す。全件を回すのは、PRを仕上げる最後の1回だけにする。全件の評価は次の手順で行う。

1. 旧版の出力を用意する。`main`の`skills/unslop/`（2026-10-22 より前は`skills/clear-japanese/`）が`run.json`の`snapshots.revised`と一致し、モデルと推論設定も同じなら、`outputs.json`の`revised`の出力を旧版として使い回す。違う場合は、旧版も手順2〜3で3回生成する。
2. 新版の`skills/unslop/`を中立な名前の一時フォルダへコピーし、全ファイルが一致することを確認する。
3. 試行ごとに新しいエージェントを使い、同じモデルと設定で3回実行する。各エージェントにはスキルと入力だけを渡し、採点基準や他の出力を見せない。下記の依頼を使い、各ケースの出力を別ファイルで保存する。読んだスキルのパスを実行記録で確認する。
4. 旧版と新版の出力を匿名ラベルで混ぜ、原文と`rubric.md`とともに採点者1人へ渡す。版の対応は伏せる。`outputs.json`は対応表を含むので、採点者には`label`・`case`・`text`だけを渡す。各必須条件の合否と出力中の根拠を記録する。
5. 主担当もすべての出力を読み、採点と照合する。旧版の失敗、新版の失敗、回帰、判定の不一致を分けて報告する。全体の文字数だけで合否を決めない。

依頼文は次を使い、`依頼.md`にはケースのIDと`prompt`だけを配置する。

> 日本語の清書をお願いします。{スキルのパス} を読み、その手順と必要な参照資料を使って、{依頼のパス} の各件を処理してください。出力は {保存先} にIDごとに .md ファイルとして保存してください。各ファイルは清書後の本文のみ。入力とスキルは変更せず、この2つ以外の文脈を調査する必要はありません。完了したら保存先のみ報告してください。

Claude Code で実行する場合は、インストール済みの unslop が自動で読まれて比較が混ざらないよう、依頼文に「インストール済みのスキルなど、指定したパス以外のスキルは使わないでください。」を足す。

## Codex CLI で再実行する

今回の記録は `run.json` に固定したスキル本文と依頼文を使う。各版・各試行に別の一時ディレクトリを作り、
スキルを `writing/`、`requests.json` を `依頼.json` としてコピーし、空の `本文/` を作る。
作業ディレクトリ名には版や評価を示す語を入れず、生成側へ rubric と他の出力を渡さない。

```sh
codex exec --skip-git-repo-check --sandbox workspace-write --json \
  --model gpt-6-astra -c 'model_reasoning_effort="medium"' \
  -C <一時ディレクトリ> '<run.json の prompt>' > <記録先>.jsonl
```

実行記録の command execution から、指定したスキルの読み込みと検出コマンドの実行を確認する。
保存された本文を匿名ラベルで混ぜ、原文・rubric とともに生成とは別の採点者へ渡す。
採点後は主担当が全出力と引用を照合する。同形の失敗が合格と不合格に分かれた場合は、判定を再確認する。
採点基準を後から緩めず、修正理由を `results.md` に残す。

```sh
python3 evals/bin/summarize-prose
```

このコマンドは試行の欠落・重複、判定根拠の有無、手書きの正誤例の判定、測定版と現在のスキルの一致を
検査し、採点済みの結果を集計する。本文の良し悪しを機械的に判定するものではない。
生成を再実行しても同じ結果になる保証はない。
