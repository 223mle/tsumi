# 指示語・範囲の検出と専門語保持の回帰評価

2026-10-27。PR #14 の初回改善版から、分野固有の名詞を検出する処理を外し、指示語・列挙・判断条件の
見直し候補を出す方式へ変更した。文章評価は変更前18/18、変更後18/18で、今回の条件では回帰はなかった。
文章品質の点数が上がったとは主張しない。

## 検出処理で直したこと

「共有ファイル」「接続先」「起動ファイル」「同梱」を固定の検出語から外した。
「これ」「それ」の指示対象、「など」の列挙範囲、「適宜」「所定の」の判断条件を問いとして出力する。
文脈を解析して合否を決める処理ではなく、正しい文章も候補に含まれる。

同じ7テストを変更前のスクリプトで実行すると、2件成功・3件失敗・2件エラーとなった。
修正版は7件すべて成功した。変更前には、分野固有の名詞の誤検出と、指示語・判断条件の見逃しがあった。
[実行結果](tool-regression.json) と [テスト](../../tests/test_unslop_ambiguous.py) を保存している。

## 文章の評価

| ケース | 変更前 | 変更後 | 確認内容 |
| --- | --- | --- | --- |
| reader-scope | 3/3 | 3/3 | 指示語をレポート・キャッシュに具体化し、順序とエラー時の操作を保持した。定義済みの共有ファイルは削除・別名化しなかった。 |
| adr-structure | 3/3 | 3/3 | 既存 API で目的を満たせることを、代替案を比較しない理由にした。 |
| decision-detail | 3/3 | 3/3 | 必須項目名と、通知が再表示される条件を保持した。 |
| retention | 3/3 | 3/3 | 削除条件と取り消せないことを保持した。 |
| pr-brief | 3/3 | 3/3 | 課題と変更を冒頭に置き、比較方針とレビューへの問いを保持した。 |
| howto-draft | 3/3 | 3/3 | 承認と期限を操作の前に置き、操作を分けた。 |

`reader-scope` には、定義済みの「共有ファイル」と、指す対象が分からない「これ」「それ」を同時に含めた。
定義済みの語を別名にする誤文と、指示語・エラー対応を曖昧なまま残す誤文も採点した。
前者・後者とも不合格となり、手書きの修正文は合格した。ADR の正誤例も含め、5件の対照例は期待どおりの判定だった。
対照例は生成の合格数に含めない。

主担当は全出力を読み、原文と判定を照合した。初回採点では「マイ予約からキャンセルする」を
「マイ予約を開く」「対象の予約をキャンセルする」と分けた1件が、操作の創作として不合格になった。
原文にないボタンや別操作は加えておらず、ほかの試行でも同種の操作分解を認めていたため、
同じ基準で再確認して合格へ訂正した。基準は変更していない。

## 条件と限界

- 変更前は `5f6a4c5` のスキル。新しい入力の `reader-scope` を3回生成し、変更していない5ケースは前回の最終版15出力を再利用した。
- 再利用時はスキル全文とモデル・推論設定の一致を確認した。旧5ケースは6件をまとめた入力、旧 reader-scope は単独入力であり、文脈が完全に同じではない。
- 修正版は全6件を各3回、新しい `codex exec` で生成した。モデルは `gpt-6-astra`、推論設定は `medium`。CLI は0.158.0。
- 生成側には指定スキルと依頼だけを渡し、判定基準は渡していない。モデルの通常設定は存在し、完全に空の環境ではない。
- 追加で実行した旧版3試行と新版3試行のすべてで、指定スキルの読み込みと検出コマンドの実行を記録から確認した。
- 採点者には版を伏せ、原文・基準・本文だけを渡した。人間の編集者による評価ではなく、主担当の照合を併用した。
- 対象を特定できる材料を与えた条件である。情報不足時の質問、自動発動、長い実装会話での初稿品質は評価していない。
- 発動条件の description は変更しておらず、トリガー評価は再実行していない。hook やインストール済みスキルも変更していない。
