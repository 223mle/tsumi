# 清書の判定基準

各ケースを下記の基準で判定する。言い回しや文字数の一致を合否にしない。各観点を pass / fail / 対象外で記録し、不合格には具体的な出力箇所を添える。適用される観点とケース別の必須条件をすべて満たした試行だけを合格とする。3試行すべて合格ならpass、一部合格ならflaky、合格なしならfailとする。採点者と主担当の判定が違う場合は理由を記録し、基準に照らして主担当が確定する。

1. **情報の保持**。原文の対象・条件・例外・時点・不確実さを保ち、原因や設計判断を創作しない。
2. **必要十分な説明**。判断に必要な要点と根拠で止める。空欄を埋めるための選択肢、一般論、注意点、検証項目や同じ結論の反復を増やさない。
3. **説明の順序**。対象や設定の用途を紹介してから条件分岐を説明する。影響の節は、その節の要点から詳細へ進む。
4. **情報のまとまり**。背景・課題・維持条件の境目を示す。独立した事実はリストにし、理由や連続する動作は関係を保って文章にする。
5. **比較の論点**。選択肢は同じ問いへの回答をまとめる。別の論点は分け、未決定を勝手に決定しない。
6. **用語の定義**。文書の中で作った呼び名は、見出し・選択肢名・表を含む初出で、誰が何をした結果のものかを具体的に定義する。定義に同じ語を使って説明を一周させない。

## ケース別の必須条件

- display-label: 影響が表示名に限られること、データ・キーの維持、移行不要、認証・権限・通信先の維持を保つ。空の選択肢は削除か短い省略理由に留める。想像のリスク・代替案・テスト計画を足さない。影響の小ささを説明するために、同じ結論を何度も言い換えたり項目別の長い説明に展開したら不合格。
- retention: 新規だけ・既存は維持・90日・毎日午前3時・取り消せない・事前ダウンロード・法的保全は除外・移行不要・周知必要をすべて残す。不可逆な削除を「影響は小さい」と弱めない。
- notice: 適用日・時間帯・窓口・承認条件・翌営業日・保存期間を残す。互いに独立した案内を段落へ詰めず、操作の連続と監査目的は自然な文にまとめる。受付時間変更を処理日の原因にしない。
- export-config: 設定ファイル・項目・用途を条件説明に先行させ、「一覧」の参照先を明記する。A/BとCの問いを分ける。省略時の互換性とCの未決定を残す。

- minor-impact: 保存データ・API項目名・権限・通信先は維持、利用者の設定変更と操作変更・外部システムの修正は不要、を残す。影響の結論と同じ内容の「総括」を重複させない。変更なしの項目をそれぞれ小節に展開せず、短い文章か箇条書きにまとめる。根拠なく意味を広げた「影響は一切ない」や新しい確認作業を足さない。
- pr-brief: 冒頭の1〜2文で、イシュー（共有テンプレートの更新がプロジェクトに反映されず、古い `theme` のまま残る）と解決策（起動時に未反映の項目を通知し、設定ファイルは書き換えない）を示す。`make fmt`・`make lint`・`make test` の成功や件数のように、どのPRでも同じ検証を本文に残したら不合格。PR固有の手動確認は残してよい。挙動は出力例で示し、比較規則の羅列を冒頭に置かない。「レビューしてほしい点」は、迷った2案・選んだ理由・確認してほしいことを問いの形で示す。理由は原文の補足にあるものを使う。`rules` の順序を比べることと、順序保持オプションの影響を残す。原文にない理由・代替案・検証を足さない。
- coined-term: 「既読テンプレート」を定義より前（決定事項の1行目の選択肢名を含む）で使わないか、選択肢名をこの呼び名を使わない表現に変える。定義では、利用者が共有テンプレートの変更を見て反映するかを判断し、`tmpl ack` を実行したときに保存するコピーであることを示す。「最後に既読にした時点のテンプレート」のように、同じ語で説明を一周させた定義が残れば不合格。3つの比較対象と選択肢の内容を保つ。
- coined-term-draft: メモから起草した決定事項で、「既読テンプレート」を定義より前（採用を示す1行目の選択肢名を含む）で使わない。選択肢名に使う場合は、その前で定義するか、選択肢名をこの呼び名を使わない表現にする。定義では、利用者が共有テンプレートの変更を見て反映するかを判断し、`tmpl ack` を実行したときに保存するコピーであることを示す。メモにある3つの比較対象と表示する項目を保ち、メモにない理由や動作を足さない。
- decision-detail: 決定事項の表の後で、判断に必要な項目（`tmpl ack` で通知を止める、更新は `tmpl ack` だけで確認時の値へ戻すと再表示する、確認済みテンプレートがない場合は差分全体を表示する、設定を書き換えない）を本文に残す。表示形式・`theme` の理由・記録前に表示する理由・自動記録の条件・比較できない場合の動作・ネットワークなどの細部は、折りたたみか短い補足にまとめる。6項目を同じ重さで並べたままなら不合格。懸念事項・影響範囲、セキュリティ境界への影響、互換性の各節は、最初の文でその節の結論を示す。必須項目のラベル（秘密情報・通信先・保存先、旧バージョン・プロジェクト設定・保存データ）は残す。すべての事実を本文か折りたたみに残し、新しいリスクや対策を足さない。

旧版で通ったケースも回帰防止として残す。旧版の不合格を確認できなかったケースを改善実績に数えない。採点者は原文と匿名化した出力だけを読み、各判定に出力の根拠を添える。
