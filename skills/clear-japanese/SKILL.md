# Clear Japanese — 読み手の理解が自然に進む文章に整える

原文と提供された文脈の意味・文体を保ち、対象が具体的で、必要な説明に絞られた文章にする。事実調査、設計の採否、承認・実装・検証の状態確認は扱わない。

## 先に情報の置き場所と説明量を決める

**原文を一文ずつ言い換える前に、構成を決める。** 元の見出しや段落をそのまま引き継ぐと、説明の混在や書きすぎも残る。短い一文の依頼では構成の整理は不要。

段落のある文章では[構成](references/structure.md)と[完成例](references/worked-example.md)を読む。ADR・意思決定の記録では[ADRの整理](references/adr.md)、PR説明では[PR説明](references/pr-description.md)も読む。

次の判断を済ませてから本文を書く。途中の分類メモは出力しない。

| 決めること | 判断 |
| --- | --- |
| 各節で答える問い | 背景は現在の状態、課題は困りごと、提案・決定は変更内容。役割が混ざる場合は配置を変える。複合見出しの中でも境目を示す。 |
| 説明の順序 | 対象や用途を紹介してから、例や条件ごとの動作へ進む。結果・影響の節では、その節の結論を先に示す。 |
| 段落か箇条書きか | 後の文が前の文の理由・具体例・条件を説明するなら段落。独立した事実・変更点・制約なら箇条書き。同じ話題というだけで文章をつながない。 |
| どこで止めるか | 要点と必要な根拠・条件が伝われば止める。見出しや空欄を埋めるための説明は足さない。影響の小さい節は短いままでよい。 |

「変更しない」を小節ごとに繰り返している場合は、重複を除き、短い文章か箇条書きへまとめる。原文の事実を残すことと、見出しの数や説明の長さを残すことは違う。根拠のない「影響なし」、一般的なリスク・対策、求められていない検証計画を補わない。

自分で起草する文書（PR説明、設計書、READMEなど）や、読み手向けの書き直しを頼まれた文書では、何を載せるかを選ぶことも書き手の仕事である。読み手が判断や操作に使わない事実（作業の過程、どの変更でも同じ検証の記録）は載せない。依頼者の原文を清書するだけの場合は、重複しない事実を残す。

## 決めた配置に沿って清書する

[意味の保持](references/preservation.md)と[つながり](references/cohesion.md)を読む。語句・文法の修正には[語彙](references/vocabulary.md)と[文](references/sentence.md)、飾りや過剰な修辞には[不自然な修辞](references/ai-smell.md)を参照する。

- 主体・動作と、それに付く条件・例外・数値・時点・不確実さを一組として移す。意味を左右する修飾語は、まず原文の表現を保つ。
- 原文にある因果・目的・対比だけを使う。「ため」「に伴い」「を受けて」などで、並列の事実に関係を付け加えない。理由が分からない場合も、接続詞で穴埋めしない。
- 同じ主体の連続する動作はまとめ、既に説明した対象を次の文で受ける。語尾や長さを変えるためだけに書き直さない。自然な原文はそのまま使う。
- 通常の清書では重複しない事実を残す。概要への短縮でも、独立した仕様・約束・実施条件を細部とみなして落とさない。特定情報を除く指示がある場合は従う。

文体は原文に合わせる。指定も原文もない場合は、です・ます調にする。

## 完成した本文を照合する

まず意味、次に構成を確認する。

1. 原文の各事実と、主体・条件・例外・数値・時点・確度が対応しているか。追加した関係表現には原文の根拠があるか。意味を変えずに直せない表現は原文へ戻す。
2. 各見出しの下の全段落が、その節の問いに答えているか。初出の対象を紹介する前に例外へ進んでいないか。別々の問いへの選択肢を同列にしていないか。文書の中で作った呼び名を、見出しや選択肢名を含めて、定義より前に使っていないか。
3. 各節の最初の文が、その節の結論や要点になっているか。テンプレートで項目が決まっている節でも、項目を並べる前に結論の文を置いているか。
4. 独立した情報を段落に詰めていないか。理由や連続する動作まで機械的に箇条書きへ分解していないか。
5. 同じ結論の反復、空欄を埋める一般論、不要な小見出しが残っていないか。削っても必要な事実・条件がすべて伝わる説明は削る。重大な制約を短さのために弱めない。

この確認で見つかった箇所だけ直す。文章の良し悪しを文字数や変更箇所の数で判断しない。

## 出力

貼り付けられた文章には清書後の本文だけを返す。ファイルの修正を依頼された場合は対象ファイルを編集し、完了を簡潔に伝える。修正理由は求められたときにだけ説明する。

HTML比較ビュー、指摘レポート、採否の確認、A/Bテスト、別エージェントへのレビュー委譲は、このスキルの清書手順に含めない。

意味を一意に決められない箇所は推測で確定せず、原文の意味の幅を保つ。それでは清書が成立しない場合に限り、必要な点を短く尋ねる。
