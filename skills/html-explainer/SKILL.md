# html-explainer

図と日本語で、読み手が仕組み・差・判断を理解できるHTMLを作る。本文は[unslop](../unslop/SKILL.md)、図は同梱のSVG部品に任せる。元資料があるときは、図の意味と情報密度を保つ。文字を大きくして縦へ並べ直すだけでは、見やすさの再現にならない。

## 構成と図を決める

1. unslopを読み、読者が答えられるべき問いを決める。提供資料を事実の起点にし、数値の単位・条件・時点・確度を保つ。推測を実測へ変えない。入力の時間を、根拠なく受付開始後の所要へ足さない。未測定の工程は秒数を仮置きせず `unknown: true` で描き、完了時刻を断定しない。初出の専門語を説明する。
2. [図の選び方](references/figure-selection.md)で、問いに合う図を選ぶ。本文・図タイトル・summary・captionへ同じ結論を繰り返さない。図のタイトルは短く、captionには条件・出典・未確認事項を置く。
3. 参照HTMLがある場合は、作成前に主要な図のスクリーンショットを確認する。色が表す対象、共通の軸、グループ、境界、前後切替の役割を拾う。本文や図の数を減らしてコンパクトに見せない。
4. 図を通じて同じ対象に同じ色を割り当てる。背景はほぼ無彩色、群の背景は淡色、値と経路に強い色を使う。色だけで状態を示さず、ラベル・線種・captionを併用する。

## 共通部品で生成する

複雑な図を標準の `flow` や表へ押し込まない。[図入力の仕様](references/diagram-input.md)に沿ってJSONを作り、次の部品を使う。

| 読み手の問い | 部品 |
| --- | --- |
| 何を先に進め、何を選ぶか | `decision`：2つの方針を同じ密度で並べる |
| どこで時間がかかり、何が重なるか | `timeline`：負の時刻・グループ帯・基準線を持つ共有軸 |
| 誰が何を送り、どこで認可するか | `network`：ノード、境界、リクエストとファイルの別経路 |
| どの量で上限を超えるか | `threshold`：線形・対数軸と閾値、超過部分 |

モデルは内容、値、ノードのグリッド位置、関係を指定する。座標・折返し・矢印の接続位置・ラベルの余白・配色は部品が決める。入らないラベルや衝突する経路が拒否されたら、説明をcaptionへ移すかグリッドを整理する。文字を小さくする、検査を外す、入力へ生のSVGを混ぜることで回避しない。

スキルのディレクトリから実行する。

```sh
python3 scripts/diagrams.py /absolute/path/figure.json --output /absolute/path/figure.html
```

`--fragment`を付けると文書へ埋め込むfigure断片になる。断片を埋め込むページには `assets/diagrams.css` と `assets/diagrams.js` を一度だけインラインで組み込む。

### 前後比較

同じ対象は全variantで同じIDを使う。軸、ノードの基準位置、色を固定する。時間図と経路図を同じ比較操作で動かす場合は、1つのbundleの `panels` にまとめる。部品が座標・幅・透明度を補間し、複数panelを同期する。別の図へ瞬時に入れ替えるだけで済ませない。

`motion: true`では経路に沿った流れも再生できる。動きは因果・経路を説明するために使い、実測の速度を意味すると書かない。画面外・タブ非表示・reduced-motionでは停止する。印刷とJS無効時には全variantが残る。

### 元のHTMLと同じ内容で作り直す

元HTMLの全figureに対応するbundleを順番に `{"figures": [...]}` へ並べる。次のコマンドが本文・見出し・表・出典を保ち、全図とページのテーマを置き換える。元のSVG座標、CSS、JSは再利用しない。図からしか値を取得できない場合は、描画位置から読み取った概数であることをcaptionに記す。

```sh
python3 scripts/compose.py source.html figures.json --output rebuilt.html
```

元資料は変更しない。元図の数とbundle数が違えば生成は失敗する。事実の照合は別に行う。元HTMLを新しいCSSで包むだけの方法を、図を再生成したことにしない。

### 新規の文書・簡単な図

[基本入力](references/input.md)と[例](assets/example.json)から本文JSONを作る。

```sh
python3 scripts/render.py document.json --output document.html
```

単独の横棒、短い直列、表はこのレンダラーでよい。高度な図は上のbundleを埋め込む。部品で表せない関係だけ[特殊なSVG](references/figure-selection.md)の手順へ進む。その場合もテーマを再定義せず、共通トークンを使う。

## 初稿を実物で検証する

初回生成で完成に近づけるため、次を納品前に行う。「一発」は無検査や全入力での成功保証を意味しない。

- 原資料と主体・条件・例外・数値・時点・確度・出典を照合する。
- 1440pxと390px、明暗テーマで開く。図の局所スクロールは許容するが、ページ全体の横はみ出しとラベル欠落は直す。
- 前後切替の途中と終点、連打、キーボード、流れの再生・停止、reduced-motion、印刷、JS無効を確認する。
- [描画検査](scripts/check-render.cjs)を実行し、スクリーンショットを実際に開く。線が無関係なノードを貫かないか、ラベルの所属を迷わないかを読む。
- 元資料があるときは、同じ幅・同じ表示状態で図とページの高さを比べる。長くなったなら、入れ子のfigure・重複見出し・値の別表化を先に減らす。本文や注釈の削除、フォント縮小で帳尻を合わせない。

```sh
node scripts/check-render.cjs document.html render-evidence
node scripts/check-diagrams.cjs document.html diagram-evidence
```

PlaywrightとChromiumを使う。必要なら既存の `NODE_PATH` と `CHROME_PATH` を指定する。[確認項目](references/verification.md)に自動検査の限界を記載している。

修正が必要なら、同じ不備を防げる共通部品を先に直し、同じJSONから再生成する。納品HTMLだけへの座標・色の手直しは、次の生成へ改善が残らない。個別編集をした場合は、その事実を報告する。

完成したHTMLを開いてリンクを返す。比較を依頼された場合は、改善した点だけでなく元資料に劣る点、初稿からの修正、未確認を短く伝える。

[参照スキルと採否](references/sources.md)は、このスキルの設計変更時だけ参照する。
