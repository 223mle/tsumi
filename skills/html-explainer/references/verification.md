# 描画後の確認

`check-render.cjs`は、PlaywrightとChromiumが利用できる環境で動く。既存のPlaywrightにブラウザーがなければ `CHROME_PATH` を指定する。確認のために依頼者の常用ブラウザーやプロファイルを操作しない。

検査はHTMLをfile URLで開き、外部通信を遮断する。1440pxと390pxで明暗テーマを撮影し、JS無効、印刷、reduced-motion、テーマボタンのキーボード操作を確認する。成果物はスクリーンショットとreport.json。

自動判定できるのは、ページの横はみ出し、ID重複、内部リンク切れ、主要な文書構造、SVG・表のラベル、JSエラー、外部依存、図中の不可視テキストなど。すべてのラベルの衝突や、読み順、意味の正しさ、出典の妥当性、全色のコントラストは保証しない。

画像を開き、次を人または実行エージェントが確認する。

- 最初の画面で題と要点が読めるか。目次が本文を押し下げすぎていないか。`check-render.cjs` は390×844pxで1つ目の要点が画面に入らなければ失敗し、後の要点がはみ出せば `notes` で知らせる（`390-first-screen.png`）。
- ステップ図は、各段階で図のどこかが変わり、説明文がその変化を言っているか。390px幅で現在の段階が見えるか。
- 用語のツールチップが本文や図を隠したまま残らないか。
- 本文の結論と、図の示すことが一致するか。図でしか分からない重要な条件を隠していないか。
- 矢印の向き・動詞・ラベルの所属が迷わず分かるか。色を見なくても対象を区別できるか。
- 長い日本語、URL、数値が重ならず読めるか。表のスクロール先にも見出しの意味が通るか。
- 印刷でタブ内の情報や図のラベルが欠けていないか。

検査の故障を検出するには、正常なHTMLが通り、幅2000pxの固定要素を追加した合成不良例が390px検査で落ちることを確かめる。これは内容品質の評価とは別である。

## SVG部品とアニメーション

`check-diagrams.cjs`は、前後の途中フレームが両端と異なること、ステップの前進・←→キー・最終段階での「次へ」の無効化・説明文の追従、同じIDのラベルが更新されること、連打後の状態、流れの再生・停止、ラベルの重なり、ラベルが自分のものではない箱・札・棒に載っていないこと、後から描かれた棒の下に隠れたラベル、SVG外への文字切れを検査する。スマートフォン幅では、ステップ図の各段階で現在の矢印が固定バーに隠れないこと、用語に触れても隠したノードが現れないことも確かめる。印刷とJS無効では全scene（ステップ図は最後のsceneと全段階の文章）が残り、reduced-motionでは補間せず切り替わることも確かめる。

SVGの線と文字のすべての交差や、色の美しさ、意味の正しさは保証しない。重なり検査の正常例と、CSSで全edge labelを同じ座標へ寄せた合成不良例を両方実行する。実測をしていない速度の差を、粒子の速さとして描かない。

## 自分でスクリーンショットを撮るとき

スマートフォン幅で図の要素だけを撮ると、固定された目次バーや操作バーが図の上に写ることがある。撮る前に図を目次バーの下までスクロールするか、要素のスクリーンショットでの重なりは撮り方によるもので、図の不具合ではないと扱う。不具合かどうかは、ページ全体の画面か `check-diagrams.cjs` の結果で判断する。

検査以外のスクリプトで図を操作する場合、比較の切り替えは見た目を整えたラジオボタン（`.dg-switch input`、`check({force: true})`）、ステップは `[data-step]` と `[data-go="1"]`、スライダーは `.dg-slider input`（値を変えて `input` イベントを送る）、全体表示は `.dg-fit-toggle`。切り替えの完了は figure の `data-animating="false"` で待つ。
