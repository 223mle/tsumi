# 野心を上げる — 深くする案と広げる案の作り方

Felix Rieseberg の記事の要点である。記事は、モデルへの依頼を高度（成果）、深さ、幅の3方向に引き上げる方法を述べている。速さも方向の1つに挙げているが、中身は扱っていない。

このスキルでは、深さは依頼文に入れ、高度と幅は「さらに引き上げるなら」の案にする。高度と幅は依頼の範囲を広げるためである。

## 深さ — 依頼文に入れる

同じ作業を、その分野の第一人者がするやり方に近づける。大きくするのではなく、一段下の材料と道具まで降りる。

- **生の材料から始めさせる。** ひな形の数字を更新させるのではなく、手に入る元のデータを渡す。
- **語彙ではなく道具を揃える。** 専門家の言葉づかいになっても、手法が変わっていなければ深くなっていない。表にまとめようとする場面で、データベースや統計モデルを使わせる。どの道具を使うかを依頼者が知らなくてよい。モデルに選ばせる。
- **高い目標を、当然の目標として書く。** 5秒かかるページなら、200ミリ秒を目標にする。モデルが無理だと答えても、解ける問題として続けさせる。依頼文では、数値と、その数値が要る理由で書く。強調のための語は使わない（[Opus 5.5 の指針](opus-5-5.md)）。
- **自分の思い込みを試させる。** 「解約は初期設定の問題だと考えている。生のデータから再現できるか試してほしい」のように、信じていることを述べ、元のデータで反証を試みさせる。
- **外の判定者を置く。** モデルに自分の成果を採点させない。実行すればすぐ結果が返る道具が最もよい。依頼文では、完了の判定手段として書く。
- **役割を演じさせない。** 「空売り投資家のように書いて」ではなく、空売り投資家が調査でする作業をさせる。役割の演技は出力をよくしない。

## 高度 — 案にする

1つの作業ではなく、その先の成果を頼む。成果がはっきりしている仕事に向き、創作には向かない。話し合いの会議が要る仕事は、高度を上げる余地がある。

- **次に何が起きるかを問う。** 「このクラッシュを直す」の先には「クラッシュが起きない状態を保つ」がある。
- **資料ではなく判断を頼む。** 四半期の報告なら、「何が変わり、なぜ変わり、何をすべきか」を頼む。分かったことを踏まえ、急ぐ判断を3つ挙げさせ、それぞれに賛否の論拠を付けさせる。
- **成果物そのものを問い直す。** その資料が果たしている目的を述べ、目的をもっとよく果たす方法を設計させる。過去の記録で効果を確かめさせ、一定期間は元の方法と並べて回す。
- **人が毎回関わらなくてよい仕組みにする。** 高度を上げると、続けて回る仕組みの話になる。モデルが自分で材料を取り、再現し、確かめられるように、先に環境を整える必要がある。

案には、追加で要るものを書く。データへのアクセス、実行環境、権限、期間である。

## 幅 — 案にする

普段は使わない分野の知識、道具、手法を持ち込む。

- **名詞を動詞に言い換える。** 「報告資料」を「忙しい人に因果の筋を信じてもらい、不確かな中で決めてもらう」と言い換えると、関係する分野が見えてくる。
- **要る役割を並べる。** よいチームなら誰がいるかを挙げる。品質には分析者、記者、編集者。反対側から試すなら、空売り投資家や不正を調べる会計士のような批判役である。役割は分野と手法を見つけるために使い、演技はさせない。
- **複数のエージェントを使う。** 幅を持ち込むと、サブエージェントに分ける構成になりやすい。

## 記事が避けるよう述べていること

- 最初に思いつく成果物で止まり、その先の成果を問わない。
- 同じ作業を大きくするだけで、深くしない。
- モデルの「できない」をそのまま受け入れる。
- 「お金を稼ぐ」のような、具体的な成果のない目標を渡す。
- すべての作業に人が挟まる形のままにする。
